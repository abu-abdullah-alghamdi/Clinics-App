# عيادتي — تطبيق Flutter

تطبيق حجز مواعيد عربي (RTL) بخط IBM Plex Sans Arabic: الدخول برقم الجوال ورمز من 4 أرقام، ثم المعلومات الشخصية، الرئيسية، الأطباء، الخدمات والسلة والدفع، مواعيدي، وحسابي، مع الشريط الزجاجي العائم وانتقالات iOS الأصلية (والسحب من الحافة للرجوع).

> رمز الدخول للتجربة: **1111**
>
> الصفحات التعريفية تطلع أول مرة بس. عشان تشوفها مرة ثانية احذف التطبيق من الجهاز أو المحاكي وشغّله من جديد.

## المتطلبات (مرة وحدة على الماك)

1. **Xcode** من App Store، ثم افتحه مرة ووافق على الشروط.
2. **Flutter**: من flutter.dev (أو `brew install --cask flutter`).
3. **CocoaPods**: `brew install cocoapods`
4. تأكد إن كل شي جاهز: `flutter doctor`
5. نسخة Flutter لازم تكون 3.35 أو أحدث (شريط التبويبات الأصلي من آبل يحتاجها)، و Xcode 26 أو أحدث. للتحديث: `flutter upgrade`

## التشغيل على Xcode

من داخل مجلد المشروع:

```bash
chmod +x scripts/dev.sh
./scripts/dev.sh run
```

السكربت يجهز مشروع iOS أول مرة، ويحمّل الحزم، ويفتح Xcode، ويشغّل التطبيق على المحاكي.
إذا طلب Xcode تختار جهاز، اختر أي iPhone من القائمة اللي فوق مرة وحدة.

## إعدادات العيادة

هوية كل عيادة وإعداداتها في ملف مستقل: `clinics/<id>/config.json` (حالياً: `demo` = عيادتي، و`noor` = عيادة نور التجريبية لاختبار تعدد العيادات).
الملف يوصل للتطبيق وقت البناء:

```bash
flutter run --release --dart-define-from-file=clinics/demo/config.json
```

- بدون الملف التطبيق يشتغل بإعدادات demo، فالأمر المعتاد `flutter run --release` يشتغل زي ما هو.
- الملف لازم يحتوي كل المفاتيح، ولو نقص مفتاح يوقف التشغيل برسالة واضحة (ما ياخذ قيم عيادة ثانية).
- `scripts/dev.sh` يستخدم ملف demo تلقائياً، ولعيادة ثانية: `CLINIC=<id> ./scripts/dev.sh run`
- المصدر في الكود: `lib/clinic_config.dart` (`ClinicConfig.current`)
- ممنوع في ملفات العيادات أي سر (مفاتيح دفع، كلمات مرور، توكنات): الملف ينضمّن داخل التطبيق. فيه اختبار يرفضها.

| المفتاح | وش هو |
|---|---|
| `CLINIC_ID` | معرّف العيادة (نفس اسم مجلدها) |
| `CLINIC_APP_NAME` | اسم العيادة في النصوص والمشاركة والتقويم |
| `CLINIC_NAME_EN` | اسم العيادة بالإنجليزي (للمتاجر والنسخة الإنجليزية مستقبلاً) |
| `CLINIC_PHONE` | رقم الاتصال (+966...) |
| `CLINIC_WHATSAPP` | رقم واتساب (+966...) |
| `CLINIC_SHARE_LINK` | الرابط مع مشاركة طبيب أو خدمة (https) |
| `CLINIC_STORE_URL` | صفحة التطبيق في المتجر لزر التحديث (https) |
| `CLINIC_MONOGRAM` | حرف الشعار (حرف أو حرفين) مكان الشعار لين تتوفر صورته |
| `CLINIC_ACCENT` | اللون المميز بصيغة `0xFFRRGGBB` (عيادتي: `0xFFE3FF3A`) |
| `CLINIC_IOS_BUNDLE_ID` | معرّف التطبيق في آيفون (عيادتي: `com.clinicsapp.clinicsApp`) |
| `CLINIC_ANDROID_APP_ID` | معرّف التطبيق في أندرويد (عيادتي: `com.clinicsapp.clinics_app`) |
| `CLINIC_SPLASH_COLOR` | لون خلفية شاشة البداية بصيغة `0xFFRRGGBB` |
| `CLINIC_ON_ACCENT` | لون النص والأيقونات فوق اللون المميز (لازم يكون واضح فوقه: تباين 4.5 أو أكثر، وإلا يوقف التشغيل) |

الألوان في الكود: `AppColors.accent` و`AppColors.onAccent` (في `lib/theme.dart`)، تنقرأ من ملف العيادة وقت البناء.
ألوان الحالات العامة (الأحمر للأخطاء، الأخضر للنجاح، الرمادي…) مشتركة بين كل العيادات.

## تطبيق مستقل لكل عيادة

كل عيادة مجلدها مستقل في `clinics/<id>/`:

```
clinics/<id>/config.json                          الهوية والمعرّفات والألوان
clinics/<id>/icon.png                             الأيقونة الأصلية (1024×1024)
clinics/<id>/ios/<id>.clinic.xcassets             أيقونة آيفون وشاشة البداية (تتولد من icon.png)
clinics/<id>/android/res/mipmap-*/ic_launcher.png  أيقونة أندرويد (تتولد من icon.png)
```

والأداة `tool/clinic.py` تجهز وتبني أي عيادة من ملفها بدون تعديل ملفات المشروع يدوياً:

```bash
python3 tool/clinic.py assets <id>             # مرة وحدة لعيادة جديدة: الأيقونات وشاشة البداية من icon.png
python3 tool/clinic.py check                   # يفحص كل العيادات (الملفات، المعرّفات ما تتكرر، الأيقونات)
python3 tool/clinic.py run <id> -d "<الجوال>"   # يشغّل تطبيق العيادة على الجوال
python3 tool/clinic.py build <id> ipa          # نسخة الإنتاج لآيفون (App Store)
python3 tool/clinic.py build <id> appbundle    # نسخة الإنتاج لأندرويد (Google Play)
```

- أندرويد ياخذ المعرّف والاسم والأيقونة ولون البداية من ملف العيادة نفسه وقت البناء.
- آيفون يقرأها من `ios/Flutter/ClinicSelected.xcconfig` اللي يكتبه `use` (و`run`/`build` يسوونه لحالهم).
  وفيه فحص أول خطوة في البناء: لو العيادة المجهزة غير العيادة اللي في ملف الإعدادات يوقف البناء.
- نسخ الإنتاج (Archive لآيفون وApp Bundle لأندرويد) ما تنبني إلا بملف عيادة صريح.
- بدون ملف (وقت التطوير) = عيادتي (demo)، فالأمر المعتاد `flutter run --release` يشتغل زي ما هو.
- التوقيع المحلي (اختياري) في `ios/Flutter/Signing.xcconfig` (ما يرتفع لـ GitHub): `DEVELOPMENT_TEAM = XXXXXXXXXX`
- لا تبني عيادتين بنفس الوقت من نفس المجلد على جهازك (Xcode يقرأ ملف إعدادات واحد). في GitHub كل بناء في جهاز مستقل.

## سحب التحديثات وإعادة التشغيل

```bash
./scripts/dev.sh update    # يسحب آخر نسخة من GitHub ويعيد البناء والتشغيل في Xcode
./scripts/dev.sh watch     # يراقب GitHub كل 30 ثانية، وأي تحديث جديد يسحبه ويشغّله تلقائياً
```

وللتطوير السريع من الطرفية مع Hot Reload: `./scripts/dev.sh sim`

## ربط المشروع بـ GitHub (مرة وحدة)

التحديث التلقائي يحتاج مستودع على GitHub:

```bash
# أنشئ مستودع فاضي على github.com باسم clinics_app ثم:
git remote add origin https://github.com/<اسمك>/clinics_app.git
git push -u origin main
```

بعدها أي تحديث ينرفع على هذا المستودع، أمر `update` أو `watch` يسحبه ويشغّله.

## إمكانية الوصول ومعايير آبل

- التطبيق فاتح دايماً (الوضع الداكن متوقف حتى لو الجوال عليه).
- "تقليل الحركة": الانتقالات تصير تلاشي بسيط، وتتوقف الحركات الثانية.
- "زيادة التباين": الشريط العائم يصير معتم بحد واضح بدل الزجاج، والبطاقات تاخذ حدود.
- تكبير الخط: كل شي يكبر مع إعداد الجوال لين الضعف، وبطاقات الخدمات ترتب نفسها عمودي مع الخط الكبير جداً.
- قارئ الشاشة يعرف اليوم والوقت المختار، والأيام المغلقة، والأوقات المحجوزة.
- حذف الحساب من صفحة "حسابي" (شرط من آبل لأي تطبيق فيه تسجيل دخول).

## ميزات آبل الأصلية

- العنوان الكبير يصغر ويثبت فوق وأنت تمرر (الأطباء، الخدمات، مواعيدي، حسابي).
- نوافذ زجاجية عائمة بمقبض سحب، ونافذة الجنسية توقف بنص الشاشة وتنسحب كاملة.
- الضغط المطوّل على بطاقة الطبيب أو الخدمة: معاينة وقائمة سريعة.
- تنبيهات ومفاتيح آبل الأصلية (إلغاء الموعد، حذف الحساب، تذكير واتساب).
- مواعيدي: اسحب لتحت للتحديث، واسحب البطاقة للتعديل أو الإلغاء.
- رمز التحقق يتعبّى من الرسائل فوق الكيبورد.
- "أضف إلى التقويم" بعد الحجز، وتنبيه من الجوال قبل الموعد بساعة.
- مشاركة الطبيب أو الخدمة بقائمة المشاركة الأصلية.

تحتاج حساب Apple Developer مدفوع (لاحقاً): الموعد على شاشة القفل والجزيرة الديناميكية، ويدجت الشاشة الرئيسية، و Apple Pay الحقيقي (مع بوابة دفع).

## الحالات الخاصة (للتجربة)

تحت "حسابي" فيه صفحة **معاينة الحالات**: التحميل، انقطاع النت، خطأ السيرفر، التحديث الإجباري، الصيانة، حركة الدفع، ونوافذ الإلغاء والحجز. تظهر في كل النسخ (حتى Release) لين نقفلها قبل النشر.

- فشل الدفع: ادفع ببطاقة رقمها ينتهي بـ 0002
- ما فيه أوقات: د. فهد محجوز بالكامل في ثاني يوم دوام
- الرمز غير صحيح: اكتب أي رمز غير 1111
- سياسة الإلغاء ومدة رجوع المبلغ في أول `lib/states.dart`

## قبل النشر الفعلي

- رقم العيادة في `lib/data.dart` (المتغير `clinicPhone`) قيمة تجريبية، غيّره لرقم العيادة.
- الفروع (الأسماء، الأحياء، الأرقام، المواقع على الخريطة، ساعات العمل) والعرض (`discount` على الخدمة) تجريبية في `lib/services_data.dart`.
- نص سياسة الخصوصية في `lib/screens/privacy_screen.dart` تجريبي، استبدله بالنص المعتمد.
- قفل صفحة معاينة الحالات: `showStatesPreview = false` في `lib/states.dart`.
- رابط المشاركة `appShareLink` في `lib/native.dart` يتبدل برابط التطبيق على App Store.

- الرمز حالياً ثابت (1111). في النسخة الحقيقية يُرسل برسالة SMS عن طريق مزوّد رسائل، ويكون عشوائي.
- البيانات (الأطباء، الخدمات، الفروع، المواعيد، الطلبات، الحسابات) محفوظة داخل التطبيق للعرض فقط، وتحتاج ربط بخادم.
- أرقام الأطباء (المرضى، التقييم، التقييمات) وتقييمات الخدمات وتعليقات المستخدمين ونبذات الخدمات (`serviceReviews` و `serviceAbout` في `lib/services_data.dart`) تجريبية: استبدلها بالحقيقية، آبل ما تقبل تقييمات وهمية.
- **الدفع شكلي**: لازم يتربط ببوابة دفع حقيقية قبل الرفع على App Store (آبل ترفض الدفع الوهمي).
  اكتب كلاس يطبّق `PaymentGateway` في `lib/payments.dart` وغيّر `PaymentGateway.instance` له، وباقي التطبيق ما يتغير.
  زر Apple Pay الحقيقي لازم يكون زر آبل الرسمي (مثلاً عن طريق حزمة `pay`).
- صور الخدمات حالياً أيقونات: استبدلها بصور حقيقية في `lib/services_data.dart`.
- نص "الشروط والأحكام" في `lib/screens/terms_screen.dart` تجريبي.
- لتشغيله على آيفون حقيقي: افتح `ios/Runner.xcworkspace` في Xcode، ومن Signing & Capabilities اختر حسابك (Team).
